StockPay API — GBP (UK) payments

Accept payments in British pounds (GBP) through a hosted card checkout. REST + JSON, server-to-server. This page is complete on its own — you don't need the INR docs.

How it works

  1. Your server creates a payment with "currency": "GBP".
  2. You redirect the customer to the returned payment_url.
  3. The customer pays by debit/credit card on a secure hosted checkout (processed by Razorpay).
  4. The customer is sent back to your return_url.
  5. You receive a signed order.paid webhook, and can also check the status at any time.

Card details never touch your server or ours — no PCI work needed on your side.

Base URL

https://stockpay-in.vercel.app/api/v1

Same base URL for test and live. The API key decides the mode: sk_test_… = test, sk_live_… = live. Test and live payments are kept apart.

Authentication

Authorization: Bearer sk_live_xxxxxxxxxxxxxxxx
Content-Type: application/json

No merchant ID or client ID — the secret key identifies the account. Keep it on your server only. Missing/invalid key → 401 unauthorized.

Create a payment

POST/orders

FieldTypeDescription
amount requirednumber | stringAmount in pounds, e.g. 24.99 or "24.99". Min 1.00, max 99,999.00. Two decimals at most.
currency requiredstring"GBP". (If omitted the payment is created in INR.)
referencestring ≤ 80Your order ID. Idempotent: the same reference returns the existing pending/paid payment instead of creating a second one.
customerobjectOptional { "name", "email", "phone" } — prefilled on the checkout. Phone with country code, e.g. "+447700900123".
notestring ≤ 200Optional description shown on the checkout.
return_urlhttps URLWhere the customer lands after paying. We append ?order_id=…&reference=…&status=… — don't trust these; confirm via Get payment or the webhook.

Request

curl -X POST https://stockpay-in.vercel.app/api/v1/orders \
  -H "Authorization: Bearer sk_test_xxx" \
  -H "Content-Type: application/json" \
  -d '{ "amount": "24.99", "currency": "GBP", "reference": "UK-1001",
        "customer": { "name": "John Smith", "email": "john@example.co.uk" },
        "return_url": "https://yourapp.com/payment/return" }'

Redirect the customer to payment_url; it forwards to the card checkout. The link is valid for 30 minutes (expires_at). amount_payable always equals amount for GBP.

Get a payment

GET/orders/{id} — same object as above. Checking the status also asks the card processor directly, so it is up to date even if a webhook is delayed.

GET/orders?reference=UK-1001 — { "data": [ … ] }, newest first.

POST/orders/{id}/cancel — cancels a pending payment.

When paid: status = "paid", amount_paid (e.g. "24.99"), currency = "GBP", paid_at, and utr = the card payment ID (pay_…) — keep it for support and refunds.

Statuses

statusMeaning
pendingCustomer hasn't paid yet. A declined card keeps it pending — the customer can retry on the same page.
paidPayment captured. Final.
expiredNot paid within 30 minutes. Create a new payment if the customer wants to try again.
cancelledCancelled by you or the merchant. Final.

There is no failed status; treat expired and cancelled as "not paid".

Test mode

  • Use your sk_test_… key — same URL and requests as live.
  • Responses have "test": true; no real money moves.
  • If the merchant has connected Razorpay test keys, payment_url opens Razorpay's test checkout — pay with Razorpay's published test card numbers (Razorpay docs → "Test Card Details").
  • Otherwise payment_url shows a Simulate successful payment button, which marks the payment paid and sends the webhook.

Webhooks

When a payment is confirmed we POST to the webhook URL set in the merchant's StockPay admin (API Keys tab):

POST https://yourapp.com/webhooks/stockpay
Content-Type: application/json
X-StockPay-Event: order.paid
X-StockPay-Delivery: 42
X-StockPay-Timestamp: 1791890000
X-StockPay-Signature: sha256=5d1c…

{ "event": "order.paid", "created_at": "…",
  "order": { "id": "ord_…", "status": "paid", "amount_paid": "24.99", "currency": "GBP", "utr": "pay_…", … } }

Verify the signature

signature = "sha256=" + hex(HMAC_SHA256(webhook_secret, timestamp + "." + raw_body)). Use the raw body, compare in constant time, reject timestamps older than 5 minutes.

const crypto = require('crypto');
function verifyStockPay(rawBody, headers, secret) {
  const ts = headers['x-stockpay-timestamp'];
  const sig = headers['x-stockpay-signature'] || '';
  if (!ts || Math.abs(Date.now() / 1000 - Number(ts)) > 300) return false;
  const expected = 'sha256=' + crypto.createHmac('sha256', secret).update(ts + '.' + rawBody).digest('hex');
  return sig.length === expected.length && crypto.timingSafeEqual(Buffer.from(sig), Buffer.from(expected));
}

Reply 2xx within 10 seconds; otherwise we retry after 1 min, 5 min, 30 min, 2 h, 6 h, 12 h and 24 h. Handle duplicates by order.id.

Node.js example

const BASE = 'https://stockpay-in.vercel.app/api/v1';
const KEY = process.env.STOCKPAY_KEY; // sk_test_… or sk_live_…

async function createGbpPayment(orderId, amountGbp, customer) {
  const r = await fetch(BASE + '/orders', {
    method: 'POST',
    headers: { Authorization: 'Bearer ' + KEY, 'Content-Type': 'application/json' },
    body: JSON.stringify({ amount: amountGbp.toFixed(2), currency: 'GBP', reference: orderId, customer,
                           return_url: 'https://yourapp.com/payment/return' }),
  });
  const data = await r.json();
  if (!r.ok) throw new Error(data.error.message);
  return data.payment_url; // redirect the customer here
}

async function getPayment(id) {
  const r = await fetch(BASE + '/orders/' + id, { headers: { Authorization: 'Bearer ' + KEY } });
  return r.json(); // { status, amount_paid, currency: 'GBP', utr: 'pay_…', … }
}
