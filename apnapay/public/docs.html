StockPay API Reference

Accept UPI payments in INR through a hosted payment page. REST + JSON, server-to-server.

Base URL

https://stockpay-in.vercel.app/api/v1

The same base URL is used for test (sandbox) and live. The API key decides the mode: sk_test_… creates test payments, sk_live_… creates real ones. Test and live payments are kept apart — a key can only see payments made in its own mode.

Authentication

Send your secret key as a Bearer token on every request. There is no separate merchant ID or client ID — the key identifies your account.

Authorization: Bearer sk_test_xxxxxxxxxxxxxxxx
Content-Type: application/json

Keys are in the StockPay admin panel → API Keys. Keep them on your server only (never in a mobile app or browser code). Missing/invalid key → 401 unauthorized.

Create a payment (hosted payment page)

POST/orders

FieldTypeDescription
amount requirednumber | stringAmount in rupees, e.g. 499 or "499.00". Minimum is set by the merchant (currently ₹100). Max ₹99,999.
currencystringOptional. Only "INR" is accepted; anything else → 400 unsupported_currency.
referencestring ≤ 80Your order ID. Idempotent: sending the same reference again returns the existing pending/paid payment instead of a new one.
customerobjectOptional { "name", "phone", "email" }.
notestring ≤ 200Optional, shown on the payment page.
return_urlhttps URLWhere the customer is sent after paying. We append ?order_id=…&reference=…&status=… — do not trust these values, confirm with Get payment or the webhook.

Request

curl -X POST https://stockpay-in.vercel.app/api/v1/orders \
  -H "Authorization: Bearer sk_test_xxx" \
  -H "Content-Type: application/json" \
  -d '{ "amount": 499, "currency": "INR", "reference": "ORD-1001",
        "customer": { "name": "Rahul", "email": "rahul@example.com" },
        "return_url": "https://yourapp.com/payment/return" }'

Redirect the customer to payment_url. The page expires at expires_at (15 minutes by default). In live mode amount_payable includes up to ₹0.99 extra so each payment can be identified; the customer pays that exact amount.

Get a payment's status

GET/orders/{id} — returns the same object as above.

GET/orders?reference=ORD-1001 — { "data": [ … ] }, newest first.

POST/orders/{id}/cancel — cancels a pending or expired payment.

Fields to read: status, amount_paid, currency, paid_at, utr (12-digit UPI reference from the bank).

Statuses

statusMeaning
pendingWaiting for the customer to pay.
paidMoney received and confirmed. Final.
expiredNot paid in time. A late payment may still turn it paid (within 24 h).
cancelledCancelled by you or the merchant. Final.

There is no failed status: a UPI attempt that fails never reaches the merchant's bank, so the payment simply stays pending until it is paid or expires. Treat expired and cancelled as "not paid".

Test mode (sandbox)

  • Use your sk_test_… key with the same base URL.
  • Payments are created with "test": true and never touch a bank account.
  • Open the payment_url — instead of a UPI QR it shows a Simulate successful payment button. Pressing it marks the payment paid and sends the order.paid webhook with "test": true.
  • There are no test card numbers: StockPay does not process cards. Payments are UPI only.

Supported currencies and methods

INR only, paid by UPI (any UPI app or QR scan). GBP, other currencies, cards, net banking and wallets are not supported.

Webhooks

Set your webhook URL in the admin panel → API Keys. When a payment is confirmed we send:

POST https://yourapp.com/webhooks/stockpay
Content-Type: application/json
X-StockPay-Event: order.paid
X-StockPay-Delivery: 42
X-StockPay-Timestamp: 1791890000
X-StockPay-Signature: sha256=5d1c…

{ "event": "order.paid", "created_at": "…", "order": { …same object as Get payment… } }

Verify the signature

signature = "sha256=" + HMAC_SHA256(webhook_secret, timestamp + "." + raw_body), hex. Use the raw request body, compare in constant time, and reject timestamps older than 5 minutes.

const crypto = require('crypto');
function verifyStockPay(rawBody, headers, secret) {
  const ts = headers['x-stockpay-timestamp'];
  const sig = headers['x-stockpay-signature'] || '';
  if (!ts || Math.abs(Date.now() / 1000 - Number(ts)) > 300) return false;
  const expected = 'sha256=' + crypto.createHmac('sha256', secret).update(ts + '.' + rawBody).digest('hex');
  return sig.length === expected.length && crypto.timingSafeEqual(Buffer.from(sig), Buffer.from(expected));
}

Reply with any 2xx within 10 seconds. Otherwise we retry after 1 min, 5 min, 30 min, 2 h, 6 h, 12 h and 24 h. The same event can arrive more than once — make your handler idempotent (e.g. by order.id).

Node.js example

const BASE = 'https://stockpay-in.vercel.app/api/v1';
const KEY = process.env.STOCKPAY_KEY; // sk_test_… or sk_live_…

async function createPayment(orderId, amountInr) {
  const r = await fetch(BASE + '/orders', {
    method: 'POST',
    headers: { Authorization: 'Bearer ' + KEY, 'Content-Type': 'application/json' },
    body: JSON.stringify({ amount: amountInr, currency: 'INR', reference: orderId,
                           return_url: 'https://yourapp.com/payment/return' }),
  });
  const data = await r.json();
  if (!r.ok) throw new Error(data.error.message);
  return data; // redirect the customer to data.payment_url
}

async function getPayment(id) {
  const r = await fetch(BASE + '/orders/' + id, { headers: { Authorization: 'Bearer ' + KEY } });
  return r.json(); // { status: 'paid' | 'pending' | 'expired' | 'cancelled', amount_paid, currency, … }
}
